# نظام تقارير غرف طوارئ ولاية شمال دارفور

نظام حقيقي متكامل لإدارة وتوثيق بيانات المنح والدعم المقدم للمحليات، مبني من الصفر بـ Node.js + Express، مع مصادقة حقيقية وصلاحيات وتقارير وإشعارات. يدعم قاعدتي بيانات: **SQLite** (افتراضياً للتشغيل المحلي) و**PostgreSQL** (للاستضافة السحابية عبر `DATABASE_URL`).

## ✨ الميزات

| الميزة | الوصف |
|--------|-------|
| 🔐 مصادقة حقيقية | JWT + كلمات مرور مشفرة (bcrypt) - بدون كلمات مرور في الكود |
| 👥 صلاحيات | مدير (Admin) يرى كل شيء، مستخدم (User) يرى تقاريره فقط |
| 📋 نظام مراجعة | التقارير تبدأ "قيد المراجعة" → يوافق/يرفض المدير مع ملاحظة |
| 📊 تحليلات متقدمة | رسوم بيانية حسب المحلية/المانح/القطاع/الشهر |
| 📝 سجل نشاطات | تتبع كامل لكل عملية (إضافة/تعديل/حذف/مراجعة/دخول) |
| 🔔 إشعارات داخلية | المستخدم يصلّه إشعار عند الموافقة/الرفض، والمدير عند تقرير جديد |
| 📄 تقارير PDF | تصدير تقرير جاهز للطباعة بالعربية |
| 📊 تصدير Excel | CSV بأرقام عربية مفصولة بفواصل |
| 🔗 روابط مشاركة | روابط مؤقتة بصلاحيات قابلة للتحديد (بدون كلمة مرور) |
| 💾 قاعدة بيانات | **SQLite محلياً + PostgreSQL للاستضافة** - بيانات حقيقية دائمة، وليست localStorage |

## 🚀 التشغيل المحلي

```bash
npm install
npm start
```

يفتح على: `http://localhost:3001`

## ☁️ الاستضافة السحابية المجانية

النظام جاهز للنشر على أي منصة تدعم Node.js 22+. الخيارات المجانية:

### قاعدة البيانات: PostgreSQL سحابي (تخزين دائم حتى على الخطط المجانية) ⭐

اضبط `DATABASE_URL` وسيتحول النظام تلقائياً من SQLite إلى PostgreSQL (يُنشئ الجداول والبيانات الأولية بنفسه):

1. أنشئ قاعدة PostgreSQL مجانية:
   - **[Neon](https://neon.tech)** - الأسهل، لا يتطلب بطاقة، بضغطة واحدة
   - **[Supabase](https://supabase.com)** أو **[Railway](https://railway.com)** كبدائل
2. انسخ رابط الاتصال `postgresql://...` وأضفه كمتغير بيئي `DATABASE_URL`
3. عند الحاجة لتشفير SSL (Neon/Supabase): أضف `PGSSL=true` (معظم الروابط تحتوي `sslmode=require` تلقائياً)

> البيانات تصبح دائمة على خادم قاعدة البيانات نفسه — لا تتأثر بإيقاف خادم التطبيق.

### الخيار 1: Render (الأسهل، بدون بطاقة) — ⭐ موصى به

1. ارفع المشروع إلى **GitHub** (لا ترفع مجلد `data/` و `node_modules/`)
2. في [render.com](https://render.com) اضغط **New → Web Service** واربط مستودعك
3. إعدادات النشر:
   - **Build Command**: `npm install --omit=dev`
   - **Start Command**: `node server/index.js`
4. أضف المتغيرات البيئية (Environment Variables):
   - `JWT_SECRET` → قيمة عشوائية طويلة
   - `ADMIN_PASSWORD` → كلمة مرور قوية
   - `DATABASE_URL` → رابط PostgreSQL (Neon) لضمان **حفظ البيانات دائماً**
5. بدون `DATABASE_URL`: يعمل النظام على SQLite لكن قرص Render Free مؤقت ويُمسح عند إعادة النشر

### الخيار 2: Railway (أفضل تجربة، يتطلب بطاقة للتفعيل)

Railway يحتوي على **مجلد دائم (Volume)** مما يحافظ على البيانات:

```bash
# رابط استضافة الملف مباشرة
railway login
railway init
railway volume add data-vol --mount-path /app/data
railway up
```

أو ببساطة: اربط مستودع GitHub بـ [railway.com](https://railway.com) → يكتشف التطبيق تلقائياً → أضف **Volume** على `/app/data`.

### الخيار 3: Docker (أي منصة)

```bash
docker build -t north-darfur-erp .
docker run -p 3001:3001 -v $(pwd)/data:/app/data north-darfur-erp
```

### ملاحظات هامة للاستضافة

- **البيانات**: بدون `DATABASE_URL` تُحفظ في `/app/data/emergency.db` — اربط Volume دائم عليها (Railway) أو استخدم PostgreSQL (Neon) لتخزين مضمون.
- **النسخ الاحتياطي**: استخدم ميزة "إنشاء نسخة احتياطية" في لوحة الإدارة بانتظام.
- **HTTPS**: معظم المنصات توفر HTTPS تلقائياً.

## 🔒 الأمان

- ✅ كلمات المرور مشفرة بـ `bcrypt` (لا تخزين نصي)
- ✅ الجلسات عبر `JWT` مع وقت انتهاء
- ✅ صلاحيات على مستوى الخادم (`requireAdmin`)
- ✅ التحقق من صحة المدخلات على الخادم
- ⚠️ غيّر دائماً: `JWT_SECRET` + كلمة مرور المدير
